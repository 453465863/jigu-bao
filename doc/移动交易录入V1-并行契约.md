# 移动交易录入 V1 并行契约

冻结日期：2026-10-02。A 交易、B 截图、C 行情分别开发，最终由主任务整合和验收。

## 账户归属

记账时从 `useStorageStore.getState().activeAccountId` 读取当前头像账户，并与本机持久化的 `activeAccountId` 再次比对。识别结果中的平台只用于冲突提醒。AI 输出不得包含 `accountId`，也不得切换账户。

## B → A：TradeDraft

```js
{
  screenshotType: 'exchange_trade' | 'otc_application' | 'otc_confirmation' | 'holding_snapshot' | 'unknown',
  platform: string | null,
  code: string | null,
  name: string | null,
  action: 'buy' | 'sell' | 'subscribe' | 'redeem' | null,
  amount: number | null,
  shares: number | null,
  price: number | null,
  nav: number | null,
  fee: number | null,
  tradeAt: string | null,
  requestAt: string | null,
  actualNavDate: string | null,
  actualConfirmDate: string | null,
  confidence: { /* 每个识别字段对应 0–1 置信度 */ },
  screenshotHash: string | null
}
```

低置信度或无法核实的字段填 `null`，不可猜测。B 只返回草稿；人工确认页填补必填字段后，由 A 的 `commitTradeDraft` 校验并记账。B 不直接写 `holdings`、`cash`、`tradeJournal`。

## C → A/首页：ETFQuote

```js
{
  code: '513300',
  marketPrice: number | null,
  quotedAt: string | null,
  source: string | null,
  status: 'available' | 'unavailable'
}
```

只有场内交易价可以写 `marketPrice`。基金 NAV 必须保留为独立概念，不得用 NAV 填补缺失的 ETF 场内价。无有效报价时，市值与未实现收益显示“行情不可用”。C 不修改交易或账户。

## A：本机账本

- `app/lib/trading/commitTrade.js` 是人工确认后的唯一交易提交入口。
- `tradeJournal` 按当前账户隔离，仅保存在本机，不加入 `SYNC_KEYS` 或 Supabase。
- 场内成交立即更新本机现金、份额、加权成本；场外申购扣现金、记待确认，但不产生份额；实际确认更新原交易，不二次扣现金。
- 预计日期与实际日期分别保存。多笔候选不能由 AI 自动选。相同原图 SHA-256 拦截；语义相似交易仅提醒并允许人工确认。

## 集成验收顺序

1. 模块测试与静态构建。
2. 无截图的手动 ETF 买卖、场外申购/确认测试。
3. 用人工草稿测试手机确认页的账户、字段、滚动与本机保存。
4. B、C 接入后，再用用户提供的金太阳 513300 和支付宝真实截图验收。不得把 HTTP 200 当作交互验收。
