# 多账户改造：阶段 1 基线与验收

状态：1A、1B、1C 已完成；1D 已接入本地账户切换和主要账本键路由，仍需实机交易验收；1E 新账户云同步待明确授权；1F 尚未完成。

## 1D 本地账本进度

- 新账户账本存放在独立 `accountLedgers` 键，按账户 ID 分桶；旧支付宝账本仍保留在原有 `holdings`、`transactions` 等键，未迁移或复制。
- 每个新账户起始为空，包含基金代码、分组、持仓、待确认交易、交易记录、定投、每日收益和目标配置的独立字段。新增账户会创建空账本。
- JSON 导出已包含 `accountLedgers`；导入时仅恢复本地尚不存在的账户账本，避免覆盖已有本地数据。完整冲突合并留在 1F 验收阶段。
- `accountLedgers` 自 2026-10-05 起参与已登录用户的 Supabase 同步，授权范围包括新账户账本、现金、交易记录和目标计划；未配置云端或未登录时保持本机存储。
- 头像菜单现在可点击账户名称切换；切换后刷新页面，以重建页面内的计算状态。支付宝保留原键，新账户的基金、分组、持仓、交易、定投、收益、目标配置等通过 `storageStore` 写入 `accountLedgers[accountId]`。
- 新账户不自动装入支付宝示例组合；本地导出把原有支付宝键和 `accountLedgers` 一起保存。导入备份需先切回支付宝，避免旧格式备份误写进新账户。
- 云同步不再因切换到新账户而暂停。新账户账本以 `accountLedgers` 顶层数据同步，与旧支付宝账户的旧键并存。
- 账户隔离烟雾测试 `tmp/account-switch-smoke.cjs` 已通过：支付宝、金太阳虚拟盘和新增真实账户的基金、持仓、交易、分组、定投、每日收益和目标配置互不覆盖，重新初始化后仍能恢复选中账户。Webpack 开发预览首页返回 HTTP 200。真实浏览器中的交易表单点击流程仍待手动验收。
- 买卖、持仓、定投、历史记录、基金转换、分红方式、待处理交易和交易记录弹框显示当前操作账户，减少误记到账户的风险。

## 1B 已实现

- `app/lib/accounts.js` 定义固定旧账户 ID `legacy`、账户字段规范化与去重。用户已确认旧账本为支付宝；首次初始化将其标为“支付宝 · 真实账户”，另建“金太阳（ETF）· 虚拟盘”资料，之后不重复补建。
- `storageStore.getAccounts()` 从 `customSettings.accounts` 读取，缺少该字段时只返回默认旧账户；`storageStore.setAccounts()` 写回该字段。账户资料可表达多个真实或虚拟账户及平台备注。
- `customSettings` 已在现有云同步比较／上传／下载及 JSON 导入／导出流程内。1B 未暴露新账户给界面，也未修改任何持仓或交易写入路径。
- 两个相关 JS 文件的 ESLint 检查通过。构建在写入旧 `.next/trace` 时因文件权限报 `EPERM`，未能完成；该文件当前所有者为 `CodexSandboxOnline`。

## 当前数据边界

- `funds` 是全局基金列表及行情资料；`holdings` 是全局持仓。
- `groups` 是基金分组；`groupHoldings` 已按分组 ID 保存独立持仓。`pendingTrades` 与 `transactions` 的交易记录可带 `groupId`。
- `dcaPlans`、`fundDailyEarnings` 也有全局／分组作用域。现有“全部”和“汇总”视图会读取多个作用域，因此仅给分组改名，不能实现账户隔离。
- `targetAllocationPlanner` 是独立本地存储键，当前未纳入云同步清单，且没有账户作用域。
- 应用使用 `storageStore` 持久化，云同步由 `useSyncManager` 收集、清洗、比较和应用数据。导入／导出另在 `app/page.jsx` 实现。

## 兼容约束

1. 现有数据映射到固定的旧账户 ID；用户已确认其属于支付宝。不得复制、清空或改写旧持仓与交易。
2. 账户 ID、账户类型（真实／虚拟）与平台备注是账户资料；同类账户可创建多个。基金分组继续是账户内的组织层级。
3. 基金行情可共享；持仓、交易、待确认交易、定投、每日收益、目标配置与汇总必须按账户隔离。真实账户汇总不能包含虚拟盘。
4. 新账户初始账本为空。不能触发当前首页的默认组合初始化向新账户写入示例数据。
5. 新增持久化数据须走 `storageStore`，并同时检查云端全量／增量同步、云端应用、导入和导出；旧格式导入仍映射到旧账户。
6. 账户删除涉及账本，须有明确确认与可恢复的导出途径；旧账户不可因误操作删除原数据。

## 阶段 1 验收样例

- 升级前后的旧账户基金、持仓、交易、分组及汇总一致。
- 新建两个虚拟账户和一个真实账户，同一 ETF 在各账户持仓数量、成本和交易互不干扰。
- 手机与电脑均可切换账户；刷新页面后维持正确账户；任何编辑或交易确认界面显示目标账户。
- 虚拟账户数据不进入真实账户汇总；目标配置不读取其他账户持仓或现金。
- 云同步、导出／导入后账户与账本边界仍正确；旧格式备份可以导入。
